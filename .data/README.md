# Data Directory

This directory contains the OCR input files and extracted data for the Cuban Maritime Data Extraction System.

## Directory Structure

```
.data/
├── Nuevo/                    # OCR input files (organized by year/month)
│   ├── 1850/
│   ├── 1852/
│   └── ... (other years)
├── extraction.db             # SQLite database (NOT included in repository)
├── extraction_backup_*.db    # Database backups (NOT included in repository)
├── output/                   # Processing logs
└── results/                  # Exported JSON and CSV files
```

## Important Notes

### Database File (extraction.db)

⚠️ **The `extraction.db` file is NOT included in the repository** because:
- It contains extracted data that is specific to each installation
- It can be very large (500MB+ for 60,000+ entries)
- It's generated locally by running the extraction process

### First Time Setup

When you first clone the project:

1. **The database will be empty** - This is normal
2. **To populate it, you need to:**
   - Place OCR files in `.data/Nuevo/YYYY/MM/` structure
   - Run extraction using `python3 main.py` → Option 4
   - Wait for the extraction to complete

### OCR Input Files

The `Nuevo/` directory should contain OCR text files organized as:

```
.data/Nuevo/
├── 1850/
│   ├── 01/
│   │   ├── 1850_01_01_HAB_DM_U_01_0_V_003-001.txt
│   │   ├── 1850_01_01_HAB_DM_U_01_0_C_003-001.txt
│   │   └── ...
│   ├── 02/
│   └── ...
├── 1852/
└── ...
```

See [README.md](../README.md) for complete file naming conventions.

### Troubleshooting

**Error: "No data in database"**
- This means no extraction has been run yet
- Solution: Run `python3 main.py` → Option 4 to extract data

**Error: "Directory not found: .data/Nuevo"**
- OCR files are missing
- Solution: Add OCR files to `.data/Nuevo/YYYY/MM/` structure

**Error: "No files found"**
- OCR files exist but don't match the naming convention
- Solution: Verify files follow pattern: `YYYY_MM_DD_HAB_DM_U_01_0_[V|C]_NNN-NNN.txt`

## File Sizes

Typical sizes after extraction:
- **extraction.db**: 500MB - 1GB (for 60,000+ entries)
- **Backup files**: Same size as extraction.db
- **Output logs**: 10-50MB
- **Exported JSON/CSV**: 100-500MB

## Backup Strategy

The system automatically creates backups before:
- Database migrations
- Year reprocessing
- Merging databases

Backups are named: `extraction_backup_YYYYMMDD_HHMMSS.db`

## Cleanup

To free up space, you can safely delete:
- `extraction_backup_*.db` files (keep only if you need to restore)
- `output/` directory (contains only logs)
- `results/` directory (can be regenerated by exporting)

**DO NOT delete:**
- `extraction.db` (contains all extracted data)
- `Nuevo/` directory (contains OCR source files)
